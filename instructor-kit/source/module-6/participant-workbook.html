L16

Generative for Compositing (6.1)

55 min
By the end you can
  • Frame generative fill as a compositing tool, not a replacement for craft
  • Extend a background with Generative Expand to fit a layout
  • Remove distractions and fill gaps with Generative Fill + a prompt
  • Generate connective elements (shadow ground, foliage, debris) to sell a composite
  • Use Harmonize to match a placed element's light and color to its background
  • Judge, mask, and hand-finish generative output, and respect its limits and licensing
Key ideas
  • A fast, fallible assistant. Like a talented but literal intern: superb at plausible texture (sky, grass, pavement, walls) and removals, unreliable at specifics (hands, text, exact brands, precise counts).
  • The loop is never "generate and ship." It is generate → pick the best of three → mask and blend → hand-fix the tells.
  • Every result lands on a new generative layer, with variations in the Properties panel. Regenerate as often as you like; each set is kept. Never flatten until the seams are blended.
  • Short prompts, small selections. "grass", "clear blue sky", or empty to match. A whole complex scene in one go makes it flail.
  • Harmonize (Photoshop 2025 and later) generates versions of a placed element with its light, color, and shadows adjusted to the background. Compare, keep the best, mask back what it shouldn't change.
  • It won't fix a weak composite. Mismatched perspective, light, or scale (Module 4) are still yours to fix. Generation fills texture; it doesn't reason about your scene.
Worked example: Harmonize a composite

Open a cramped or messy composite: yours from Module 4, or the practice parts (l16-cramped-scene.jpg with l16-pasted-subject.png placed hard against the right edge, as in l16-cramped-composite-preview.jpg). Save as l16-composite-working.psd.

  1. Give it room. Crop tool (C), options bar Fill: Generative Expand. Drag the canvas edges outward, commit, leave the prompt empty, click Generate. Pick the cleanest variation in the Properties panel. Check the new edges at 100% (Ctrl/⌘ + 1) for repeats or seams. Tip: hide the pasted subject while you expand, so the model continues the scene, not the person.
  2. Remove distractions. Lasso a distracting object with a little margin (include its shadow). Generative Fill with an empty prompt. If a variation leaves a smudge, regenerate or clean it with the Healing Brush.
  3. Grow connective tissue. Select ground beneath the pasted subject and prompt something like gravel with small shadows, or generate foreground foliage to overlap an edge. Mask each generative layer so it only contributes where you want.
  4. Harmonize the subject. If it still looks lit by a different photo, select its layer and run Harmonize (contextual task bar or Properties panel). Compare the variations with the original; keep the best; mask back wherever it changed something it shouldn't (an edge, a face, a logo).
  5. Finish by hand. Matching grain and a touch of sharpening on the generated regions; dodge & burn to marry their light to the scene; one unifying grade over everything (Lesson 4.3).

Where did the AI succeed, and where did I have to take over?

Watch out
  • Grayed out or missing? Update Photoshop, sign in, check the network and your credits. Harmonize needs a single pixel or Smart Object layer above a background; its location can shift between releases (search Help ▸ Photoshop Help or the Discover panel).
  • Softer than the rest? Generated pixels often carry less fine detail than your capture. Match the grain and add a little sharpening.
  • Faces, hands, text, logos, product details, repeat patterns drift. Artifacts may show only at 100%: zoom in and audit.
  • Licensing. Firefly models are designed to be commercially safe, but current versions can also offer third-party partner models with different terms. For client work, check which model you used and confirm the terms.
Recipe card: Generative Assist
  1. Generative Expand (Crop out + empty prompt) for room
  2. Generative Fill + empty prompt to remove distractions
  3. Short prompts, small selections for connective texture
  4. Harmonize a placed subject to the scene, then mask back what it shouldn't change
  5. Keep each result on its generative layer; mask, don't flatten
  6. Grain/sharpen-match, hand-blend, then one unifying grade

Mantra: the model gives you a head start, never the finish line.

A note on honesty

For journalism or documentary work, generative changes may be off-limits. Disclose edits when integrity matters. It is a tool, like the Healing Brush; the judgment of what to keep, blend, and reject is still yours.

L17

Advanced Actions & Conditionals (6.2)

50 min
By the end you can
  • Record a clean, reusable Action and re-order or re-record steps
  • Insert stops, menu items, and modal pauses for input
  • Add a Conditional so one Action handles landscape and portrait differently
  • Batch an Action across a folder and save out automatically
  • Build a droplet, a drag-and-drop executable for your workflow
Key ideas
  • Action = a recorded macro. Conditional = an if inside it. Batch = the Action pointed at a folder. Droplet = that batch saved as an icon you drop files onto.
  • Record relative, not absolute. Image Size records fixed dimensions; File ▸ Automate ▸ Fit Image scales the long edge. Set Preferences ▸ Units & Rulers to Percent before recording crops and selections.
  • Actions capture what you did, not what you meant. Record on a representative file; test on your weirdest one.
  • Insert Conditional tests the document or active layer: Document Is Landscape, Portrait, or Square; Document Mode Is RGB or CMYK; Document Is 16 Bits Per Channel; Document Has Layers; Layer Is Type or Smart Object. No condition for pixel size or a layer's name.
  • A true batch asks no questions. Override Action "Save As" Commands, Suppress File Open Options Dialogs, Suppress Color Profile Warnings, Log Errors To File, and dialog toggles off.
Worked example: a Delivery Action

Use a folder of mixed landscape and portrait copies (practice: l17-input/), keep the watermark (l17-watermark.png) outside that folder, and make an empty output folder beside it.

  1. Record the core. Window ▸ Actions ▸ new set Delivery, new action Web Delivery, Record. File ▸ Automate ▸ Fit Image at 2000 × 2000 px (it scales the long edge to 2000), Unsharp Mask, Place your watermark PNG, Layer ▸ Flatten Image, Save As JPG. Stop recording.
  2. Add the branch. Set Preferences ▸ Units & Rulers to Percent, then record two tiny helper actions in the same set: Crop Wide and Crop Tall. In Web Delivery, select the first step, then panel menu ▸ Insert Conditional: If Document Is Landscape play Crop Wide, else Crop Tall. The conditional lands below the selected step, so drag it to the top: crop first, then Fit Image, so the final long edge is still 2000 px.
  3. Batch it. File ▸ Automate ▸ Batch: Action = Web Delivery, Source = your folder, Destination = an output folder, tick Override Action "Save As" Commands, set naming. Run, and watch landscape and portrait each crop correctly.
  4. Make a droplet. File ▸ Automate ▸ Create Droplet, point it at Web Delivery, save it to your desktop. Drag a folder of new images onto it.

Record Layer ▸ Flatten Image before Save As: while the watermark is its own layer, Save As won't offer JPEG.

Watch out
  • Works on one image, breaks in the batch? Almost always an absolute value: a fixed crop, a hard-coded Image Size, or a named layer that doesn't exist in every file. Re-record relative and route odd files with conditionals.
  • All files in one folder when you wanted subfolders? Override Action "Save As" Commands sends every save to the Batch destination. Set Destination to None and let the Action's own Save As steps decide.
  • Rulers still in Percent? Set them back to Pixels when you finish recording.
Actions vs droplets vs scripts: which one when?
ToolBest for
ActionRepeatable steps; with conditionals, repeatable steps on mixed input
DropletHanding that Action to someone else as a drag-and-drop icon (it runs when files are dropped on it; it doesn't watch a folder)
ScriptLoops, math, external data, or decisions Actions can't express (scripts can even call Actions)
Recipe card: Actions & Batch
  1. Window ▸ Actions → new set + action → Record relative steps (Fit Image; rulers in Percent)
  2. Insert Conditional to branch (landscape / portrait / square / mode)
  3. Insert stops / modals only where human input is truly needed
  4. File ▸ Automate ▸ Batch over a folder, Override Save As, suppress dialogs, log errors
  5. Create Droplet for a drag-and-drop reusable

Mantra: if you'll do it twice, record it once.

L18

Data-Driven Graphics & Scripting (6.3)

60 min
By the end you can
  • Define Variables that bind layers to data: text, visibility, and pixel replacement
  • Import a Data Set from a CSV and preview each row on the canvas
  • Export Data Sets as Files to render one graphic per row
  • Understand where scripting begins and read a simple ExtendScript / JS example
  • Choose between Actions, Variables, and scripts for a given job
Key ideas
  • Template + data. The template is your design with certain layers marked as variable; the data is a table where each column maps to a variable and each row is one output.
  • Exactly three kinds of variable: Text Replacement (swap the words in a type layer), Pixel Replacement (swap the image in a layer, with fit rules), Visibility (show or hide a layer).
  • The variable name binds. Each variable binds to the CSV column whose header matches its name. Names can't contain spaces and must start with a letter, underscore, or colon. Naming the layer the same is a helpful habit, not a requirement.
  • The CSV rules: UTF-8 with a header row; Visibility values true/false (Photoshop rejects yes/no); Pixel Replacement values as full file paths, or just file names with the images in the same folder as the CSV.
  • Export Data Sets as Files renders one PSD per row (for JPG or PNG, run the PSDs through an Action).
  • Scripting begins when you need loops, math, renaming by pattern, an API, or decisions based on pixel values. Photoshop runs ExtendScript (.jsx) and newer UXP scripts (.psjs) via File ▸ Scripts ▸ Browse.
Worked example: a data-driven batch

Design a simple card with a name (type layer), a photo (image layer), and a "SALE" badge (a layer to show/hide). Practice parts are in l18-data/: l18-card-background.jpg, six photos l18-ana.jpg … l18-fay.jpg, l18-sale-badge.png, and l18-cards.csv. Save your template in that same folder. The photo layer must be a pixel layer (if you placed it as a Smart Object, Layer ▸ Rasterize ▸ Smart Object).

  1. Name everything. Rename the layers exactly name, photo, sale. You'll give the variables the same names, and the CSV headers must match the variable names.
  2. Define variables. Image ▸ Variables ▸ Define. On name tick Text Replacement; on photo tick Pixel Replacement (set the method: Fit, Fill, As Is, or Conform); on sale tick Visibility. Name each variable to match its CSV header.
  3. Import and proof. Image ▸ Variables ▸ Data Sets… ▸ Import your CSV. Tick Use First Column For Data Set Names. With Preview on, step through a few rows and confirm the name, photo, and badge update on canvas. Fix any binding that didn't take (usually a header/variable-name mismatch, yes/no instead of true/false, or a photo path Photoshop can't find).
  4. Export the batch. File ▸ Export ▸ Data Sets as Files. In File Naming, choose Data Set Name, add any fixed text you like, and export. Photoshop writes one PSD per row. Optional: run them through your L17 delivery Action to flatten to JPG.

Where scripting begins: read it before you write it

The lesson's example (practice copy: l18-resize-folder.jsx). Run it with File ▸ Scripts ▸ Browse, on a copy of a test folder: it writes its web_ files into the folder it reads from.

// resize-folder.jsx  —  File ▸ Scripts ▸ Browse to run
var inputFolder  = Folder.selectDialog("Choose a folder of images");
if (!inputFolder) { throw new Error("No folder chosen."); }
var files = inputFolder.getFiles(/\.(jpg|jpeg|png)$/i);

for (var i = 0; i < files.length; i++) {
    var doc = app.open(files[i]);
    var longEdge = 2000;
    var scale = longEdge / Math.max(doc.width.value, doc.height.value);
    doc.resizeImage(doc.width * scale, doc.height * scale);

    var out = new File(inputFolder + "/web_" + doc.name.replace(/\.[^.]+$/, ".jpg"));
    var opt = new JPEGSaveOptions();
    opt.quality = 10;
    doc.saveAs(out, opt, true);
    doc.close(SaveOptions.DONOTSAVECHANGES);
}
alert("Done: " + files.length + " images resized.");

In plain English, what does the loop do to each file? Which two numbers would you change first?
