Instructor Kit · Facilitator Guide

Module 6: Generative + Automation, Advanced

How to teach the three lessons that add speed and scale to everything the course has built so far: generative tools as a fast, fallible compositing assistant (including Harmonize), conditional Actions batched over a mixed folder, and data-driven graphics from a template plus a CSV, with a first readable script. The theme of the day: design the work once, then let the machine repeat it, and keep your judgment for the parts only you can do.

3 lessons Session 6 · 3 hrs incl. break Lessons L16–L18 Level Intermediate Needs internet + credits (L16)

How to Use This Guide

  • Same rhythm as every module: Frame → Demo → Guided build → Solo variation → Check. Each lesson plan gives a timing table, a demo script with Say: lines, the lab, the mistakes to pre-empt, a check for understanding, and differentiation notes.
  • Demo live, one step at a time, and let the room do each step before you move on. Name every menu path and both shortcut forms: Ctrl on Windows is ⌘ on Mac, Alt is ⌥.
  • Teal = hands-on, amber = watch-outs. Today's watch-outs come in three flavors: environmental (sign-in, credits, network) for L16, "recorded something absolute" for L17, and "the names don't match" for L18.
  • Lesson codes: the kit numbers lessons by file (L16–L18); the site calls them Lessons 6.1–6.3. Quiz answers below match the workbook's Self-checks; the Answer Key explains each one.
The #1 risk of Module 6: the generative features are not available in the room

Generative Fill, Generative Expand, and Harmonize run in Adobe's cloud. Each learner needs Photoshop 2025 or later (Harmonize is a recent addition, and its exact place in the interface can shift between releases), an internet connection, to be signed in to an Adobe account, and generative credits (every Generate spends them). Classroom networks and lab licenses are the usual failure points. At least a day before, on one room machine: sign in, generate once with Generative Fill, once with Generative Expand, and run Harmonize once on a placed layer. On the day, everyone signs in during the warm-up, not when L16 starts.

Fallback plan if credits, sign-in, or network fail

1. Reorder. L17 (Actions, conditionals, Batch, droplets) and L18 (Variables, Data Sets, scripting) are 100% offline. If the network is down at the start, teach L17 and L18 first and return to L16 when it recovers. 2. Share. If only some accounts have credits, pair learners: one generates, both judge the variations, then swap for the Harmonize step. 3. Offline equivalents. Run the generative demos from your machine (or a screen recording made during the readiness check) and have learners do the same jobs with tools they already own: room with the Crop tool dragged outward and Fill: Content-Aware Fill; removal with the Remove tool or Content-Aware Fill on a separate layer; connective tissue by hand (Clone Stamp for gravel, a painted contact shadow as in L11 Step 2); Harmonize by hand with the L11 method (a clipped 50% gray Dodge & Burn layer plus a clipped Color Balance or Photo Filter to push the subject's light toward the scene's), then the L12 unifying grade. The compositing judgment survives intact; only the "describe it in words" part is lost. 4. Homework. Learners with credits at home repeat the L16 build there.

Lesson Plans

L16

Generative for Compositing (Lesson 6.1)

50 min
Objectives
  • Frame generative fill as a compositing tool, not a replacement for craft
  • Extend a background with Generative Expand to fit a layout
  • Remove distractions and fill gaps with Generative Fill + a prompt
  • Generate connective elements (shadow ground, foliage, debris) to sell a composite
  • Use Harmonize to match a placed element's light and color to its background
  • Judge, mask, and hand-finish generative output, and respect its limits and licensing
Timing
3mThe goal (lesson slider) + mental model: a fast, fallible assistant
3mThe generative workflow + Harmonize: where each command lives
3mLimits, ethics & licensing; "it won't fix a weak composite"
34mGuided build: Steps 1–5 (6 + 8 + 8 + 6 + 6)
3mNow You: start "generate the same fill five times" (finish at home)
4mSelf-check, recipe card, journal
Teaching sequence & live-demo script
  1. The goal (1m). Show the L16 slider: cramped and signed on one side, extended and clean on the other. Say: "Generative fill did the grunt work, new sky and ground and the sign gone, so the time goes into composition instead of cloning. Fill the gaps, not the vision."
  2. Mental model (2m). Write the loop on the board: Select → prompt (short or empty) → 3 variations, pick the best → mask + finish by hand. Say: "Treat it like a talented but literal intern. Superb at plausible texture, sky, grass, pavement, walls, and at removals. Unreliable at specifics: hands, text, exact brands, precise counts. It never ships raw."
  3. Where things live (3m). Say: "Make a selection and the contextual task bar offers Generative Fill. For Expand, it's the Crop tool with Fill set to Generative Expand in the options bar. Harmonize appears when a placed layer sits above a background: in the task bar or the layer's Properties panel. All three write to a new layer and cost credits." Show the Properties panel's variations list once.
  4. Limits and licensing (3m). Faces, hands, readable text, logos, product details, and repeat patterns drift; generated regions can be softer than the capture; artifacts hide until 100%. Say: "Adobe designs its Firefly models to be commercially safe, but current versions can also offer third-party partner models with different terms. For client work, know which model you used and check the terms. And for journalism or documentary work, generative changes may be off-limits." Then the warning box: Say: "It fills texture; it doesn't reason about your scene. Wrong perspective, light, or scale from Module 4 is still yours to fix."
  5. Set up (part of Step 1). Open l16-cramped-scene.jpg, File ▸ Save As l16-composite-working.psd. File ▸ Place Embedded l16-pasted-subject.png and drag it hard against the right edge with the feet near the bottom, as in l16-cramped-composite-preview.jpg. Name the layer subject. Say: "This is the awkward composite: framed too tight, a SALE sign fighting for attention, and a figure lit cold from the left in a warm scene lit from the right, with no shadow."
  6. Step 1: Give it room (6m). Hide the subject layer (Say: "so the model continues the plaza, not the person"). Crop tool (C), options bar Fill: Generative Expand, drag the left and right edges outward (a modest amount), commit, leave the prompt empty, Generate. Cycle the variations in the Properties panel and keep the cleanest. Show the subject again. Zoom to 100% (Ctrl/⌘ + 1) and pan along both seams looking for repeats: the buildings and the wall's joints are the tell.
  7. Step 2: Remove distractions (8m). Click the Background layer. Lasso (L) around the SALE sign and its post and its cast shadow, with a little margin. Say: "Leave the shadow behind and you've removed the sign but kept the evidence." Task bar ▸ Generative Fill, empty prompt, Generate. If a variation leaves a smudge, regenerate, or clean it with the Healing Brush on a new layer.
  8. Step 3: Grow connective tissue (8m). Draw a flat, wide selection on the ground around and just left of the subject's feet (sun from the right means shadows fall left). Prompt gravel with small shadows, Generate. Paint the generative layer's mask so it only contributes near the feet. Say: "Short prompt, small selection. Ask for a whole scene and it flails." If no variation gives a believable contact shadow, paint one by hand on a layer below the subject, exactly as in L11.
  9. Step 4: Harmonize the subject (6m). Select the subject layer, then Harmonize in the contextual task bar or the Properties panel. Compare the variations with the original by toggling the eye. Keep the best, then mask back to the original wherever Harmonize changed something it shouldn't: an edge, the face, the jacket's zip line. Say: "Same rule as every generative result: compare, keep, mask, finish."
  10. Step 5: Finish by hand (6m). Add matching grain and a touch of sharpening to the generated regions; dodge & burn to marry their light to the scene. Then one unifying grade over everything (the Module 4 finish, L12). Say: "The single step that makes a generative fill invisible is matching the grain." Save the layered file with every generative layer and mask intact.
Lab: Harmonize a Composite, then Now You

Guided build on the learner's own layered Module 4 composite, or on the practice parts (l16-cramped-scene.jpg + l16-pasted-subject.png, placed as in l16-cramped-composite-preview.jpg), saved as l16-composite-working.psd. Solo variation: generate the same fill five times and study the differences; remove three increasingly hard distractions from l16-three-distractions.jpg (a sign, a person, a hard shadow across the bicycle) and note where the AI succeeds and where they take over; turn a phone snapshot into a wide banner with Generative Expand. Start in class, finish at home. Details in labs/module-6/README.md.

Circulate for: every result on its own generative layer (nothing flattened); lasso selections with margin that include the sign's shadow; learners actually cycling variations; masks painted on the generative layers; someone zoomed to 100% on each seam.

Definition of done: the lesson's six-item checklist: canvas extended and edges audited; a distraction removed cleanly; a connective element generated and masked in; the subject harmonized (or light matched by hand) with unwanted changes masked out; generated regions grain- and sharpen-matched and hand-blended; one unifying grade over the whole result.

Mistakes to pre-empt
  • "Generative Fill is grayed out" or "Harmonize isn't there." Check sign-in, network, and version first. For Harmonize, the target must be a single pixel or Smart Object layer sitting above a background; a group, an adjustment layer, or the Background itself won't offer it. The lesson's FAQ: its location can shift between releases, so search Help ▸ Photoshop Help or the Discover panel. Two minutes of debugging, then the fallback plan.
  • Expanding with the subject visible. The model tries to continue the person at the edge. Hide the subject while expanding and removing.
  • Removing the sign but not its shadow. A shadow with nothing casting it is a bigger tell than the sign was.
  • One giant selection with a long prompt. Mushy, low-detail results. Several small, well-selected passes with short prompts.
  • Accepting Harmonize wholesale. It can alter edges, faces, and product details. Compare with the original and mask back what it shouldn't touch.
  • Flattening before blending. Once flattened, the variations and masks are gone. Keep every generative layer until the seams are finished.
  • Judging at fit-to-screen. Soft patches, repeats, and seams show only at 100%.
  • Expecting it to fix structure. A subject with the wrong perspective or scale stays wrong after any amount of generation. Fix it by hand first (L10).
Check for understanding: self-check + journal

Answers: Q1 C) Select, prompt short or empty, pick the best variation, then mask and finish by hand; Q2 A) Crop tool with Fill: Generative Expand, drag the edges outward, commit, Generate; Q3 D) Lasso the sign, its post, and its shadow with a little margin, empty prompt, Generate; Q4 B) Matching a placed element's light, color, and shadows to its background; Q5 D) Add matching grain and a touch of sharpening; Q6 A) Which model produced it (Firefly or a partner model) and its terms for your account and deliverable. Cold-call: "The subject's perspective is wrong. Which generative tool fixes that?" (None: fix it by hand first.) Full set in the Answer Key.

Journal (3 min, finish at home if needed): Where does generative fill genuinely save you time, and where does trusting it cost you more time cleaning up than doing it by hand? Draw your own line between the two.

Differentiation

Fast finishers: the lesson's "Going further": generate a busy background, then composite a cleanly cut subject (Module 1 masking) on top, so the subject stays pixel-perfect and only the surroundings are AI. Or the banner challenge: a snapshot to a wide banner by expanding in bites, with every seam fixed by hand until it is undetectable.

Struggling learners: Steps 1, 2, and 4 only: room, one removal, Harmonize, each checked at 100%. Skip connective tissue and hand-paint the contact shadow instead (they know how from L11). The must-haves are "separate layers, compare variations, mask back."

L17

Advanced Actions & Conditionals (Lesson 6.2)

45 min
Objectives
  • Record a clean, reusable Action and re-order or re-record steps
  • Insert stops, menu items, and modal pauses for input
  • Add a Conditional so one Action handles landscape and portrait differently
  • Batch an Action across a folder and save out automatically
  • Build a droplet, a drag-and-drop executable for your workflow
Timing
3mThe goal (lesson slider) + mental model: record, branch, batch
3mThe Actions panel tour + "record relative, not absolute"
3mWhat a Conditional can and cannot test; Batch settings for a hands-off run
30mGuided build: Steps 1–4 (9 + 10 + 6 + 5)
2mNow You: pick one challenge (finish at home)
4mSelf-check, recipe card, journal
Teaching sequence & live-demo script
  1. The goal (1m). Show the L17 slider: 200 images by hand versus one Action batched. Say: "If you've done a task twice, Photoshop can do it a thousand times. The setup cost is paid back the second time you run it."
  2. Mental model (2m). Board: Record → if landscape? → Crop Wide / Crop Tall → Batch. Say: "An Action is a recorded macro. A Conditional is an if inside it. A Batch points it at a folder. A droplet is that batch as an icon." Then the two reliability rules: record relative (percentages and Fit Image, not fixed pixels), and remember that Actions capture what you did, not what you meant, so record on a representative file and test on odd ones.
  3. The panel (3m). Window ▸ Actions. Point out the set folder, record, play, stop, the checkmark column (the step runs), and the dialog toggle (the step pauses for input). Double-click a step to re-record its values; drag steps to re-order. Say: "Image Size records fixed dimensions. Fit Image scales by the long edge, so it survives a portrait file."
  4. Conditionals and Batch (3m). Read the list from the lesson: Document Is Landscape, Portrait, or Square; Document Mode Is RGB or CMYK; Document Is 16 Bits Per Channel; Document Has Layers; Layer Is Type or Smart Object. Say: "There is no condition for pixel size or for a layer's name. When you need that, you need a script, which is next lesson." Then the hands-off Batch settings: Override Action "Save As" Commands, Suppress File Open Options Dialogs, Suppress Color Profile Warnings, Errors: Log Errors To File.
  5. Step 1: Record the core (9m). Open l17-input/l17-delivery-01.jpg (landscape). Actions panel: new set Delivery, new action Web Delivery, Record. File ▸ Automate ▸ Fit Image 2000 × 2000 px; Filter ▸ Sharpen ▸ Unsharp Mask (80% / 1.0 / 0, as in the lesson's figure); File ▸ Place Embedded l17-watermark.png, position it, commit; Layer ▸ Flatten Image; File ▸ Save As JPEG, quality 10, into l17-output/. Stop. Say: "Flatten is what lets Save As offer JPEG: a JPG can't hold the watermark layer. Skip it and the batch saves the wrong format or stops." (See the note in the Answer Key.)
  6. Step 2: Add the branch (10m). Preferences ▸ Units & Rulers ▸ Percent. Record two tiny helper actions in the same set: Crop Wide (on the landscape file, a Crop tool crop, for example to 16:9) and Crop Tall (on l17-delivery-02.jpg, for example to 4:5). The lesson leaves the exact crops to you; pick shapes the room can recognize. Undo the test crops. In Web Delivery, select the first step, then panel menu ▸ Insert Conditional…: If Current Document Is Landscape, Then Play Action Crop Wide, Else Play Action Crop Tall. Say: "It lands below the selected step, so drag it to the top: crop first, then Fit Image, so the long edge is still 2000."
  7. Step 3: Batch it (6m). File ▸ Automate ▸ Batch: Set Delivery, Action Web Delivery, Source Folder l17-input/, Destination Folder l17-output/, tick Override Action "Save As" Commands, both Suppress boxes, Errors: Log Errors To File, and a naming pattern (document name + extension). Turn off the Unsharp Mask dialog toggle if it's on. OK, and let the room watch the white keylines: landscape files lose their top and bottom edges to Crop Wide, portrait files to Crop Tall. Say: "The square file, 03, isn't landscape, so it takes the Else branch. That's what 'test on your weirdest file' is for."
  8. Step 4: Make a droplet (5m). File ▸ Automate ▸ Create Droplet, point it at Web Delivery, save it to the desktop with the same Batch-style options. Drag a folder onto it. Say: "It runs when files are dropped on it; it doesn't watch a folder. Hand it to a colleague who never opens a menu." Finally, set Units & Rulers back to your usual unit (Pixels) before moving on.
Lab: A Delivery Action, then Now You

Guided build on a copy of l17-input/ (eight JPEGs: four landscape, three portrait, one square, long edges 2000 to 3000 px, each labeled with its number, orientation, and size and framed by a white keyline) with l17-watermark.png kept outside the input folder and an empty l17-output/ beside it; or the learner's own mixed folder of copies. Solo variation: three sizes into three subfolders in one run (Batch Destination None), a Document Has Layers conditional, or a colleague-proof droplet with a Stop step. Details in labs/module-6/README.md.

Circulate for: the red record dot actually on before the first step; Fit Image, not Image Size; Units & Rulers set to Percent before recording the crops; the conditional dragged to the top; Override ticked in Batch; eight files in l17-output/ and the input folder unchanged.

Definition of done: the lesson's five-item checklist: a recorded, relative delivery Action (Fit Image, percent-based crops); a conditional branching landscape versus portrait; a batch that runs the folder hands-off with Override Save As; errors logged and no mid-run dialogs; a working droplet on the desktop.

Mistakes to pre-empt
  • Recording Image Size or a pixel-positioned crop. Works on the recording file, breaks on the rest. Fit Image for size; Percent units before recording crops.
  • Expecting a percent crop to give the same ratio everywhere. It trims the same share of each image. On files of different ratios the result differs a little; that's why the branch exists, and why you test on odd files.
  • Conditional left below the first step. Fit Image runs first, then the crop shrinks the long edge below 2000. Drag the conditional to the top.
  • Watermark inside the input folder. Batch processes it too, and the Place step may point at a file that moves. Keep it in a fixed place outside the input folder.
  • Batch stops halfway on a dialog. A dialog toggle is still on (often Unsharp Mask), or a profile/open-options warning appeared. Toggles off, both Suppress boxes on, errors logged to a file.
  • Files land in the wrong folder. Override Action "Save As" Commands not ticked; Batch obeyed the recorded Save As instead.
  • Forgetting to press Stop, so browsing and fixes are recorded too. Delete the stray steps from the panel.
  • Rulers left in Percent for the rest of the course. Every later dialog reads oddly (and scripts that read document size can misbehave). Reset to Pixels at the end of L17.
Check for understanding: self-check + journal

Answers: Q1 B) Fit Image scales the long edge, so it works on landscape and portrait files alike; Q2 C) Set Preferences ▸ Units & Rulers to Percent; Q3 D) Document Is Portrait; Q4 A) Drag it to the top of the list so the crop runs before Fit Image; Q5 C) Override Action "Save As" Commands, both Suppress options, and Log Errors To File; Q6 B) None, and let the Action's own Save As steps decide. Full set in the Answer Key.

Journal (3 min): List three repetitive tasks in your own workflow. For each, could an Action do it, or do you need a conditional or a script? Sorting them is the start of automating your practice.

Differentiation

Fast finishers: the three-sizes Action (thumb, web, print into three subfolders; Batch Destination None, because Override sends every save to one folder), or a Document Has Layers conditional that plays the full delivery on layered masters and a lighter "already flat" version otherwise. Going further: list the tasks Actions couldn't handle; they are L18's opening.

Struggling learners: record Web Delivery and batch it without the conditional first (Fit Image handles both orientations on its own). Once that batch works, add the two crop helpers and the conditional. If recording goes wrong, delete the bad step and re-record only that step rather than starting over.

Teaching sequence & live-demo script
  1. The goal (1m). Show the L18 slider. Say: "When the brief is 500 name badges, you stop designing files and start designing a template plus data. Ten or ten thousand costs the same effort."
  2. Mental model (2m). Board: data.csv columns → variables → layers. Write the three types: Text Replacement (swap the words in a type layer), Pixel Replacement (swap the image in a layer, with fit rules), Visibility (show or hide a layer). Say: "There are exactly three kinds. Almost any personalized-graphics job breaks down into those three."
  3. Tour and naming rules (4m). Image ▸ Variables ▸ Define; Image ▸ Variables ▸ Data Sets… ▸ Import; File ▸ Export ▸ Data Sets as Files. Open l18-cards.csv in a text editor on the projector. Say: "Each variable binds to the CSV column whose header matches its variable name. A stray space or a capital letter breaks it. Variable names can't contain spaces and must start with a letter, underscore, or colon. Visibility values are true or false; Photoshop rejects yes/no. Pixel values are full paths, or just file names with the images in the same folder as the CSV." Point out that the photo file names in the CSV match the files in l18-data/ exactly.
  4. Where scripting begins (5m). Show the lesson's resize-folder.jsx and read it as English: pick a folder; list its JPGs and PNGs; for each one open it, compute a scale for a 2000 px long edge, resize, save a web_ copy at JPEG quality 10, close without saving. Say: "You can already follow this. That's the point: reading and adapting a snippet is a real skill before you ever write one. Scripts do loops, math, renaming by pattern, and decisions that Actions and Variables can't." Mention the two flavors: classic ExtendScript .jsx and newer UXP .psjs, both via File ▸ Scripts ▸ Browse.
  5. Build the template (part of Step 1). Open l18-data/l18-card-background.jpg, Save As l18-card-template.psd inside l18-data/. Open l18-ana.jpg and drag it in as a normal pixel layer, sized to fill the white-framed window (it is 800 × 800 px, the same as the window). Type layer Ana centered in the name band. File ▸ Place Embedded l18-sale-badge.png at the top-right corner of the photo. Say: "Pixel Replacement needs a pixel layer. If you placed the photo as a Smart Object, Layer ▸ Rasterize ▸ Smart Object first."
  6. Step 1: Name everything (6m). Rename the layers exactly name, photo, sale. Say: "The variables get the same names, and the CSV headers must match the variable names. Matching the layer names too is a helpful habit, not a requirement."
  7. Step 2: Define variables (10m). Image ▸ Variables ▸ Define. Layer name: tick Text Replacement, variable name name. Layer photo: tick Pixel Replacement, variable name photo, method Fit (the options are Fit, Fill, As Is, and Conform). Layer sale: tick Visibility, variable name sale.
  8. Step 3: Import and proof (9m). Switch to the Data Sets page (Image ▸ Variables ▸ Data Sets…), Import l18-cards.csv, tick Use First Column For Data Set Names. With Preview on, step through the rows: Ana has the badge, Ben doesn't, Cy does. Say: "The name tag inside each photo is there for proofing: the tag must match the name on the card." Then the troubleshooting demo with instructor/l18-cards-broken.csv (import it into a copy of the template, or talk through it on the projector): header Name with a capital N, yes/no in the sale column, and a photo name that doesn't exist (l18-benn.jpg). Say: "Those three faults are 90% of 'why didn't it bind?'"
  9. Step 4: Export the batch (9m). File ▸ Export ▸ Data Sets as Files: choose an output folder (for example l18-cards-out/), Data Set: All Data Sets, File Naming: Data Set Name plus any fixed text. Export. Photoshop writes one PSD per row. Say: "Six cards from one template. The deliverable is this folder." Optional finish: run the PSDs through the L17 delivery Action to flatten to JPG; see the note in Mistakes about the Action's crop.
Lab: A Data-Driven Batch (Module 6 deliverable), then Now You

Guided build on the practice parts in l18-data/ (card background, six 800 × 800 photos named l18-ana.jpg … l18-fay.jpg, the sale badge, and l18-cards.csv with the columns name,photo,sale), or on the learner's own template and a small CSV of their own. Circulate for: the photo layer is a pixel layer, not a Smart Object; variable names exactly name, photo, sale; the template saved in the same folder as the CSV and photos; Preview on and several rows proofed before exporting; File Naming set to Data Set Name.

Definition of done: the lesson's Module 6 checklist: variable names (and layers) matching the CSV headers exactly; Text, Pixel, and Visibility variables defined; the CSV imported as a data set with several rows proofed on canvas; Data Sets exported as files with a clear naming pattern; (optional) finished via a delivery Action or droplet.

Mistakes to pre-empt
  • Pixel Replacement isn't offered for the photo layer. It's a Smart Object (Place makes one) or a type/shape layer. Rasterize it, or drag the photo in from an open document.
  • Header and variable name don't match. Name vs name, a trailing space, or a space inside the name. The variable name is what binds, not the layer name.
  • Visibility written as yes/no, Y/N, or 1/0. Only true and false.
  • "Can't find the image." The photo file names in the CSV don't match the files exactly, or the images aren't in the CSV's folder. Bare file names only work beside the CSV; otherwise use full paths.
  • Spreadsheet app saves the CSV oddly. Keep it UTF-8 with a header row. If Excel or Numbers changed it, open it in a text editor and check.
  • Running the cards through the L17 Web Delivery Action as-is. Its conditional crop trims a share of every card (they are portrait, so they get Crop Tall), and Fit Image enlarges a 1080 × 1350 card to a 2000 px long edge. For cards, duplicate the Action and delete the conditional and Fit Image steps (keep a Flatten before the Save As), or use File ▸ Scripts ▸ Image Processor.
  • Running the sample script on the only copy of a folder. It writes its web_ files into the same folder, and a second run processes those too. Always a test copy. And if rulers are still in Percent from L17, set them back to Pixels first: the script reads the document's width and height, and those follow the ruler unit.

Differentiation

Fast finishers: the VIP ribbon and tint layer from l18-cards-vip.csv (Ben, Eli, and Fay are VIP; Cy and Eli are tinted); then the script challenge: change the long edge and output format, and add a line that skips files already starting with web_. Going further: a data set feeding a template whose art lives in linked Smart Objects (Module 5), exported by an Action (L17), a genuine production pipeline.

Struggling learners: one variable first. Define only the Text Replacement on name, import, and step through the rows. When that works, add sale (Visibility), then photo (Pixel). Re-import the CSV after each change to the definitions. The script reading is "follow along," not "type along."
